# villaintzy-agent — Agent Games (zkVerify) Wildcard entry

An autonomous **bounty & forecast agent** for Web3 competitions, built for
[Agent Games](https://agentgames.zkverify.io) Season 01 (**Wildcard track**).

The agent lives at a public HTTPS endpoint and speaks the Agent Games agent
protocol: the platform dispatches signed tasks, the agent verifies each
signature, does its work, and returns a signed JSON result. It is designed as
the always-on "hands" for a competition workflow — scanning bounties,
forming calibrated forecasts, and producing structured, verifiable answers —
while the human operator keeps account control, secrets, and final approvals.

## What it does

- **Forecast tasks** — accepts prediction questions and returns a structured
  answer + confidence. The handler is a clean slot where a real forecasting
  model (market data, base rates, calibration) drops in; the shipped default
  is a deterministic placeholder so behaviour is reproducible in testing.
- **Bounty tasks** — accepts research/bounty briefs and returns a structured
  work plan and findings slot, ready for a research pipeline to fill.
- **Anything else** — unknown task types get a well-formed, signed
  acknowledgement, so the agent is protocol-conformant from day one.
- **Preflight** — answers the platform's signed connectivity check with
  `{ ok: true, protocolVersion: "v1" }`, as required before task dispatch.

## Architecture

```
Agent Games platform ── signed POST ──▶  POST /agent  (this service)
                                          │ 1. verify HMAC-SHA256 (timing-safe)
                                          │ 2. route by task `type`
                                          │ 3. sign the JSON response the same way
                         signed JSON  ◀───┘
GET /health ──▶ { ok: true }   (unsigned liveness probe)
```

- **Zero dependencies** — Node.js built-ins only (`node:http`, `node:crypto`).
  No npm install, no build step, nothing to patch.
- **Files**
  - `server.js` — the whole service: signature verification, preflight,
    task router (`taskHandlers` — one function per task type).
  - `selftest.js` — spins the server up with a dummy secret and verifies the
    full signed round-trip (preflight + sample task + bad-signature rejection).
  - `.env.example` — configuration template.

## Protocol notes

- Requests arrive as `POST` with header
  `x-agent-games-signature: <HMAC-SHA256 hex of the raw request body>`,
  keyed with the agent's secret.
- Responses are signed identically: HMAC-SHA256 hex of the raw response body
  in the same `x-agent-games-signature` response header.
- The secret is generated by the platform, shown **once** at agent
  registration, and supplied to this service as the environment variable
  `AGENT_GAMES_HMAC_SECRET`. It is never stored in this repo.
- At least one practice task must be completed after registration; dispatch
  is capped (10/hour), so the service is stateless and answers in
  milliseconds — well inside the 60-second response budget.

## Running

```sh
export AGENT_GAMES_HMAC_SECRET='<the one-time secret from registration>'
export PORT=8080                    # optional, default 8080
node server.js
# -> [agent] villaintzy-agent listening on :8080 (POST /agent, GET /health)
```

Expose port 8080 behind any standard HTTPS tunnel/reverse proxy and register
the full handler URL, e.g. `https://<your-host>/agent`.

## Deploy on Vercel

The same agent also ships as a Vercel serverless function (`api/agent.js`,
logic ported 1:1 from `server.js`), for when no always-on host is available:

1. On [vercel.com](https://vercel.com), sign in with GitHub → **Add New… →
   Project** → import this repo (`agentgames-wildcard-agent`) → **Deploy**.
   No build command and no install step are needed (zero dependencies).
2. `vercel.json` rewrites `/agent` → `/api/agent` and sets a 60-second
   function limit, so the public endpoint is
   `https://<project>.vercel.app/agent` — register that URL on Agent Games.
3. **After** registering the agent on Agent Games, copy the one-time secret
   into **Project Settings → Environment Variables** as
   `AGENT_GAMES_HMAC_SECRET` and redeploy. Until it is set, the function
   answers signed traffic with HTTP 503 (secure by default).

Verify the handler locally with `node test-vercel.js` (mock req/res,
signed preflight + forged-signature rejection; see `vercel-test-output.txt`).

## Testing

```sh
node selftest.js
# SELFTEST: ALL CHECKS PASSED
```

The self-test uses a throwaway dummy secret and verifies both directions of
the signature convention, the preflight contract, and that unsigned/forged
requests are rejected with HTTP 401.
